# Opening: Defense

The charge says this should not go ahead as described. It should, because the plan as written is small, checks itself, and gives a pipeline that has never run its first contact with real data.

1. **It checks itself before it claims anything.** Step 4 says to run "today's plan with the measured timings on those arrivals and check it reproduces roughly the delays the video showed" before the agent is run at all. The record already says that "if the simulated 'today's plan' does not roughly match the delays measured on video, any improvement shown would not be credible." The obvious objection is that the simulator might be wrong. The plan answers it: a wrong simulator gets caught at step 4, before any improvement is claimed.

2. **It is honest about its scope.** The record says one clip "would be a demonstration rather than the main evaluation; the report's numbers would still come from the multi-seed experiments." So the objection that "n = 1 proves nothing" doesn't apply, because the plan never asks the clip to prove anything statistically.

3. **It is the first real end-to-end test of a pipeline that has never run.** Right now "no footage has been recorded yet" and "the detection, RL training and experiments have not run yet." A 20-minute clip sends real Nairobi traffic through See (YOLO + ByteTrack + homography), then the replay scenario, then Control. It will show integration failures early, while there is still time before "24 April 2027".

4. **It is cheap and builds on what already exists.** It needs "a high, fixed camera position", "a stopwatch", and one new "recorded" scenario in a live console that "was just built" and already shows "signals switching automatically through the project's safety shield". Weighed against the cost of a one-time recording, what the project learns makes it worth doing.

5. **It fits the project's own title.** "A Video-Driven Machine Learning Pipeline". Replaying measured video arrivals against the measured fixed plan delivers that promise directly, which a viva panel will look for.

**Concessions.** Until the agent and forecaster are trained, the comparison runs against "a stand-in rule" and "a stand-in" forecaster, so any result before then demonstrates the console and does not demonstrate the project's RL. The record also does not say whether replaying fixed arrivals can capture how demand responds to the agent's signal changes.
